EXPERIMENT STATUS

예측을 실제로 수행했습니다.

2025년의 시간 순서 데이터를 학습·검증·테스트로 나누어 세 모델을 비교했습니다. 선택은 검증 구간에서, 최종 성적은 손대지 않은 테스트 구간에서 한 번만 확인했습니다. 즉, 이는 실제값이 이미 있는 과거 홀드아웃 구간을 대상으로 한 out-of-sample 예측 실험이며, 2026년 이후의 운영용 예측 파일을 별도로 발행한 것은 아닙니다.

비교한 세 가지 접근

복잡성 자체가 목표가 아니므로, 설명 가능한 기준선부터 선형 모델, 비선형 트리 앙상블 순으로 같은 입력과 분할에서 비교했습니다.

01 / SELECTED

Seasonal naive

주간 반복 기준선 · 학습 없음

같은 역·노선·방향 시리즈의 7일 전 수요를 그대로 다음 주 같은 요일의 예측값으로 사용합니다. 주간 반복이 강한 데이터에서는 가장 먼저 이겨야 할 기준입니다.

02 / LINEAR

L2 정규화 선형 회귀

범주형 변수는 one-hot 인코딩, 수치형 변수는 표준화한 뒤 선형 관계를 추정합니다. alpha=10으로 계수가 과도하게 커지는 것을 억제했습니다.

03 / NON-LINEAR

HistGradientBoosting

히스토그램 기반 그래디언트 부스팅

120 trees · lr 0.08 · 31 leaves

앞선 나무의 오차를 다음 나무가 보완하는 방식의 트리 앙상블입니다. 역·요일·과거 수요 사이의 비선형 상호작용을 학습할 수 있으며, 범주형 값은 ordinal 인코딩했습니다.

성능은 데이터 분할이나 평가 지표가 바뀌면 공정하게 비교할 수 없습니다. 모든 모델에 동일한 시간순 분할과 MAE·RMSE·WAPE를 적용합니다.

MODEL BENCHMARK

테스트 기간의 결과

TEST PERIOD

MAE는 평균 절대 오차(명), RMSE는 큰 오차를 더 크게 반영한 값, WAPE는 전체 실제 수요 대비 오차 비율입니다.

CURRENT DECISION

—

검증 MAE가 가장 낮았고, 테스트에서도 평균 —명·전체 수요의 — 오차로 가장 안정적이었습니다. Ridge와 HistGradientBoosting은 더 많은 정보를 사용했지만 이 기준선을 넘지 못했습니다.

왜 이런 결과인가

역별 수요에는 요일 단위 반복이 강하고, 이번 원본에는 날씨·공휴일 유형·행사·운행 장애 같은 외부 설명 변수가 없습니다. 복잡한 모델은 신호보다 잡음을 더 학습할 수 있습니다.

VALIDATION VS. TEST

선택 과정과 마지막 성적을 분리

선택은 검증 MAE로, 보고는 테스트 성능으로 합니다. 두 기간 모두 숫자가 낮을수록 좋습니다.

METRIC GUIDE

숫자를 어떻게 읽나?

네 지표는 서로 다른 종류의 실수를 보여줍니다. 특정 값 하나가 아니라 서로 보완하는 지표들을 함께 보고, 어느 지표가 의사결정에 맞는지 명확히 합니다.

MAE / PRIMARY SELECTION

평균적으로 몇 명 차이 났나

MAE = mean(|actual − prediction|)

각 예측과 실제값의 차이를 절댓값으로 바꾼 뒤 평균낸 값입니다. ‘평균 1,008명 차이’처럼 승객 수 단위로 바로 해석할 수 있어 모델 선택의 주지표로 사용했습니다.

RMSE / LARGE ERROR CHECK

큰 빗나감에 더 민감한가

RMSE = √mean((actual − prediction)²)

오차를 제곱하므로 드물지만 큰 실패가 있을 때 MAE보다 빠르게 커집니다. MAE가 낮아도 RMSE가 유난히 높다면 특정 날짜·역에서 큰 오차가 있는지 점검해야 합니다.

WAPE / NETWORK-SCALE ERROR

전체 수요 대비 오차 비율

WAPE = Σ|actual − prediction| / Σ|actual|

절대 오차의 합을 실제 수요의 합으로 나눕니다. 수요 규모가 다른 노선·역을 함께 볼 때, 네트워크 총량 대비 어느 정도 빗나갔는지 보여줍니다.

sMAPE / RELATIVE ERROR CHECK

0에 안전한 상대 오차

sMAPE = mean(2|a − p| / (|a| + |p|))

실제값과 예측값의 합을 분모로 사용한 대칭 비율 오차입니다. 0이 있는 저수요 구간에서도 계산 가능하도록 0 분모는 0으로 처리하며, 이번 비교에서는 보조 지표입니다.

LEAKAGE GUARD

미래를 보지 않는 세 가지 규칙

예측 성능이 좋아 보이지만 실제 배포 시 재현되지 않는 문제를 막기 위한 최소 조건입니다.

01 / 시간 정렬
각 역·노선·방향 시리즈를 날짜순으로 정렬한 뒤 lag와 rolling feature를 만듭니다.
02 / 과거만 사용
lag 1·7·14·28과 최근 7일 평균은 예측 기준일보다 이전 값만 사용합니다. 필요한 이력이 없는 첫 행은 미래 값으로 채우지 않습니다.
03 / 마지막 기간 보존
테스트 기간은 모델과 설정을 고르는 데 쓰지 않습니다. 검증 기간에서 선택한 구성을 한 번만 평가합니다.
